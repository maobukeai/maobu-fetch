# 百度网盘浏览器接管验收

首轮范围是用户在百度网盘官网点击下载，Chrome 或 Edge 产生普通 HTTP 下载，已配对的扩展按现有接管规则处理。浏览器保留自己的下载，直到桌面端确认能够读取文件且接受了任务。

## 交接条件

- 扩展使用浏览器最终下载地址、该地址匹配的 Cookie 和浏览器请求头。文件大小必须已知，地址必须为接管范围内的百度网盘 HTTPS 域名。
- 签名接口 `POST /v1/tasks/verify-baidu-download` 只读取第一个字节。成功要求 `206`、匹配的 `Content-Range` 总长度、文件类型和恰好一个响应字节。地址超出范围、重新跳转、验证页、忽略 Range 或超时均由浏览器继续。
- 桌面任务把交接的对象按文件下载，使用现有 HTTP 续传和分片校验。登录页或错误响应无法作为成功文件交付。

## 版本兼容

新接口沿用本地桥的扩展 Origin 校验、配对、签名和限流。现有 `/v1/tasks` 请求和响应格式不变。旧桌面端缺少验证接口时，新扩展将这次百度网盘下载交还浏览器。联合验收应同时加载包含本次改动的桌面和扩展构建。

## 实网验收

1. 用有权下载的无敏感文件，在本机提前计算原始 SHA-256。记录桌面构建、扩展版本、浏览器和样本类型。
2. 在已配对的 Chrome 中登录百度网盘，从分享页点击下载，核对猫步只有一条任务且完整落盘，比较字节数和 SHA-256。
3. 用同一样本验证桌面离线时浏览器下载继续，桌面端不产生对应任务。官网如果只允许在官方客户端操作，记录实际提示和条件。

## 本地验证

- Rust 专项测试覆盖成功读取指定字节、响应长度或类型不符、错误状态、重定向和目标域名限制。
- 扩展模拟测试覆盖先验证后入队、入队后取消浏览器任务、验证失败回退、临时绕过和文件大小规则。
- Chrome 和 Edge 使用各自的临时配置运行真实扩展与本地桥。未签名请求返回 `401`，带有效签名的非百度地址返回 `400`，且没有访问目标或生成下载任务。普通接管与离线回退下载的文件均通过 SHA-256 检查。
