# 猫步下载器：下载内核、BT、持久化与任务生命周期深度审查

审查日期：2026-10-31。范围：HTTP 下载、Range 并发、续传、任务生命周期、文件操作、SQLite、BT/librqbit。本报告只审查与复现，未修复以下内核问题。主审查中另行实施的完成提醒交互调整不属于本文件的修复范围。

## 证据与范围

- **隔离复现**：提取未修改的生产函数或生产配置构造代码，在系统临时目录编译执行；不等同于经过 Tauri、前端和数据库的完整应用复现。
- **代码确证**：从实际调用链可确定存在该行为；附上能够触发的输入或状态，尚未运行完整应用场景。
- **并发风险推断**：代码允许问题时序，但需要真实调度与网络时序验证，不冒充已复现事故。
- 首轮全量 Rust 测试结果由主审查统一提供：库测试 **1212 passed / 9 ignored**，`tests/range_server.rs` **9 passed**。新增完成提醒兼容测试后最终为 **1213 passed / 9 ignored**，Range 仍为 **9 passed**。通过这些测试不代表下面的问题不存在。
- 未访问、修改或删除真实用户数据库和下载文件。删除行为验证仅针对 `%TEMP%` 下新建的独立哨兵文件。

## 逐项分析与修改建议

### CORE-01：ETag 比较错误

- 位置：`src-tauri/src/manager.rs:5943`，尤其 `5949–5950`；错误预期已写入 `src-tauri/src/manager/tests.rs:924–932`。
- 行为：`remote_resource_changed()` 使用 `old.eq_ignore_ascii_case(new)`。注释和测试把 HTTP 头名称不区分大小写误套到了 ETag 值。
- 触发：下载了一部分 ETag 为 `"ABC123"` 的文件，远端改为另一版本并返回 `"abc123"`，继续下载。函数仍报告资源未变化。
- 影响：旧分片可以和新版本数据拼接；文件长度正确也无法证明内容正确。
- 复现：原函数直接提取编译，输出 `etag_case_changed_detected=false`。没有联网下载或接触真实文件。
- 修改建议：ETag 值严格逐字符比较；明确弱 ETag 的续传政策；修正现有错误测试，不要把错误预期继续当作保障。
- 验收：相同大小但内容、ETag 大小写不同的本地资源；暂停后切版本再恢复，必须进入远端变化确认流程，旧分片保留。依据：[RFC 9110 §8.8.3.2](https://www.rfc-editor.org/rfc/rfc9110.html#name-comparison)。

### CORE-02：单连接续传缺少范围和实际响应校验

- 位置：`src-tauri/src/manager.rs:3636–3649`；最终检查在 `3753–3761`。
- 行为：已有临时文件时发送 `Range: bytes={existing}-`，仅凭状态为 206 决定追加。没有调用已经存在的 Content-Range 解析器，也没有校验本次响应的起始偏移、结束偏移、总长度或实际响应验证器；该请求也没有设置 If-Range。
- 触发：本地已有前 100 字节，服务器对 `bytes=100-` 返回错误的 `Content-Range: bytes 200-299/200` 及 100 字节数据。当前路径可以把它追加到旧文件；若最终长度等于记录总长度，长度检查不能发现内容错位。错误或缺失 Content-Range 同理。
- 影响：单连接路径的完整性保护弱于多连接路径，可能把内容错位文件标为完成。探针检查无法替代后续实际数据响应检查。
- 修改建议：所有 206 统一校验 Content-Range 和验证器，采用强验证器 If-Range；只有完全匹配才能追加。服务器返回 200 时明确从零重下；416 结合现有长度和远端长度处理。
- 验收：真实调用生产单连接路径，分别注入错误起点、错误总长、缺失 Content-Range、探针后切换版本、200 回退和 416；任何错误响应不得拼接进旧文件。

### CORE-03：Range 重试上限形同虚设

- 位置：`src-tauri/src/manager.rs:4128`、`4380–4423`、`4429–4458`；`src-tauri/src/manager/work_stealing.rs:281–297`。
- 行为：窗口内重试耗尽产生 `transfer_result=Err` 后，协调器把窗口重置为 Pending，普通错误仅等 100ms 后继续外层领取；新一次领取重置窗口内重试计数。429/503 分支也没有总次数或总等待时间上限。打开分片文件失败在 `4113–4123` 同样不断重新领取。
- 触发：探针正常，正式 Range 持续返回错误 Content-Range、403/500，或者临时文件目录无法写入。设置 `max_retries=0/1` 仍可能持续请求或持续重试文件操作。
- 影响：长期 0 速度、永不失败、占用队列槽位；任务级超时检查在传输函数外，无法终止这个内部循环。
- 修改建议：区分可恢复窗口续接与终态错误；把重试预算与截止时间存入任务/窗口共享状态，耗尽后上抛并取消同任务连接；429/503 尊重有界退避与 Retry-After。
- 验收：生产 DownloadManager 对持续错误服务器应在有限请求数和有限时间内进入可操作的 Failed/WaitingNetwork 状态；保留分片，手动重试才能重置预算。

### CORE-04：暂停取消和任务超时没有覆盖全部等待点

- 位置：`src-tauri/src/manager.rs:3639`、`3672–3675`；超时检查 `1683–1705`，传输等待 `1709–1713`；客户端总超时 `6796`。
- 行为：单连接 `.send().await` 和 `stream.next().await` 没有与取消 token 做 select。取消检查发生在收到下一块之后。任务总超时仅在开始一次传输前检查，没有给传输 Future 设置 deadline。
- 触发：服务器接受连接后不返回响应头，或返回部分 body 后保持连接静默；此时点击暂停/取消。短任务超时设置同样不能及时终止当前传输。
- 影响：界面可以先显示暂停，但旧连接和 worker 仍等待数据；最长受 24 小时客户端超时影响。删除流程的一秒等待无法保证这些 worker 已退出。
- 修改建议：响应头等待、body 等待都 select 取消；整个传输统一包围任务截止时间；退出/暂停需要等待 worker 停止与数据 flush 的明确结果。
- 验收：本地“只回头不发 body”“发一块后静默”“不回头”三种服务，暂停/取消均在明确短时限内关闭连接；任务超时按配置触发并落库。

### CORE-05：暂停/恢复生命周期存在 worker 重叠风险

- 位置：`src-tauri/src/manager.rs:560–561`、`615–619`、`1633–1643`、`1954–1955`；删除超时等待 `869–874`。
- 证据等级：**并发风险推断，未完成真实 Tauri 场景的端到端时序复现**。
- 可触发时序：暂停立即从 controls 移除并 cancel 旧 token → 旧 worker 尚未完全退出 → 用户立即恢复使任务重新排队 → 新 worker 因 controls 不含任务而启动 → 旧 worker 收尾无条件 remove 同一 id 的 controls 和 task_runtime。
- 影响：旧 worker 可能移除新 worker 的控制句柄；新 worker 失去可暂停入口，任务可能被重复调度。同一临时文件由重叠 worker 操作还存在完整性风险。CORE-04 的静默连接会显著扩大重叠窗口。
- 修改建议：controls 同时记录 worker generation/JoinHandle；停止时先标记 stopping，待该代 worker 退出再允许恢复；清理时仅删除本代句柄；删除不能超时后继续假装 worker 已退出。
- 验收：受控服务器中反复快速暂停/恢复/删除，断言每个任务每一代只有一个写入者，旧代不能删除新代句柄，删除后不得 upsert 复活任务。

### CORE-06：BT fastresume 实际未启用持久化

- 位置：`src-tauri/src/bt/mod.rs:180–185`。
- 依赖证据：本地使用 `librqbit 9.0.0`；依赖 `src/session.rs:491` 的默认 `persistence=None`，`658–679` 在此配置下选择 NonPersistentBitVFactory。
- 行为：应用指定了 `fastresume: true` 和 DHT 持久化文件，却没有设置 SessionOptions 的 torrent session persistence。DHT 路由表持久化不等于任务/分片 fastresume 持久化。
- 复现：提取原配置构造代码，使用本项目实际编译的 librqbit 依赖执行，输出 `fastresume=true`、`session_persistence_enabled=false`。该检查不启动会话、不联网。
- 影响：应用自己的任务行仍在 SQLite，但 librqbit 的 torrent 会话/分片快照不会按需求写入应用 session 目录；重启必须重新添加并重新校验文件，不能把现有测试说成已验证 fastresume。
- 修改建议：显式启用 Json SessionPersistenceConfig 并指定应用数据目录下的专属路径；初始化和写入失败必须向用户报告；恢复时按 infohash 和稳定任务绑定去重。
- 验收：隔离应用数据目录中真实完成部分 BT 下载，优雅退出和强制终止各一轮，检查持久化文件及恢复进度；两个应用数据目录不能共享 torrent 状态。

### CORE-07：BT 同名数据所有权与删除范围不安全

- 位置：`src-tauri/src/bt/mod.rs:270–290`、`873–897`；BT 新任务默认 `CollisionPolicy::Rename` 在 `src-tauri/src/manager.rs:837`。
- 行为：BT 直接使用展示名构造目录，`overwrite: true` 无条件开启，未执行任务的 rename/overwrite/skip。删除仅确认目标位于下载目录之下，然后对整个同名目录 `remove_dir_all`；没有校验目录是否由当前任务创建，也没有按种子实际文件清单删除。
- 触发：下载目录已有同名文件夹，内含用户自己的文件；BT 使用同名输出后，用户选择删除任务文件。即使不在种子清单里的原文件也会被删除。
- 复现：原 `delete_task_files` 函数直接提取执行，目标为 `%TEMP%` 中新建的 ExistingUserFolder，含无关哨兵文件；输出 `deleted_roots=1`、`unrelated_user_file_still_exists=false`。没有删除真实用户文件。
- 影响：潜在覆盖与误删既有用户数据，违反重名策略。路径位于下载目录内只能防越界，不能证明其所有权。
- 修改建议：任务创建时原子分配独立输出目录并持久化；严格执行碰撞策略。删除只处理实际属于该任务的文件及空目录，包含其他文件时保留目录并提示。
- 验收：同名目录预放哨兵；下载、重启、删除任务后哨兵始终存在。重复 infohash/同名不同种子也不能共享删除所有权。

### CORE-08：BT 文件选择并未更新引擎

- 位置：`src-tauri/src/bt/mod.rs:519–520`；`src-tauri/src/lib.rs:129–150`；前端 `src/components/BtDetailsPanel.tsx:93–104`。
- 行为：引擎 `select_files()` 完全不使用 task id 或 indices，始终返回 Ok。命令仅保存元数据，UI 随后显示“文件选择已更新”。同一 session 的已有 binding 恢复时直接 unpause，也不应用新 only_files。
- 触发：下载多文件种子，取消一个文件并保存，或暂停后更改文件勾选再恢复。
- 影响：被取消的文件仍继续下载；重启前后的行为可能不一致。进度查询又把所有文件 `selected=true`，刷新列表无法反映引擎真实选择。BT 轮询持有旧 task 快照持续 upsert，还可能覆盖刚保存的选择。
- 修改建议：调用 librqbit 的实际选择更新接口；成功后读取引擎真实列表再保存；校验至少一个合法索引；轮询只更新进度字段，避免全行覆盖最新用户设置。
- 验收：局域网双文件种子，取消文件后引擎选择立即变化；暂停/恢复和重启保持选择；没有“保存成功但继续下载”的情况。

### CORE-09：BT 限速控制与统一总限速缺口

- 位置：`src-tauri/src/bt/mod.rs:132–146`、`285–290`、`524–532`；HTTP 独立 BandwidthScheduler 在 `src-tauri/src/manager.rs:138`。
- 行为：只给 session.ratelimits 设置全局值；AddTorrentOptions.ratelimits 使用默认无限制，没有读取 `task.per_task_speed_limit`，运行中也没有同步任务限速。HTTP 与 BT 分别各拿到一份全局速度值，未共享总预算。
- 触发：给正在下载的 BT 任务设单任务限速；或全局设 1 MiB/s 后同时下载 HTTP 和 BT。
- 影响：BT 单任务限制无效；HTTP 与 BT 同时运行时合计可能接近两倍全局值。这不是声称已实测特定网络吞吐，而是两套独立额度的代码事实。
- 修改建议：接入 librqbit 的 torrent 级 ratelimits，并同步运行时变更；明确统一总速率的分配方式，保证 HTTP 与 BT 合计受限；上传限制也必须落到相应引擎限制器。
- 验收：局域网可控 seeder 与 Range 源同时跑，分别验证 BT 单任务下载/上传限制、HTTP+BT 合计全局限制和动态变更。

### CORE-10：BT 统计有推算和文件长度冒充进度

- 位置：`src-tauri/src/bt/mod.rs:405–413`、`454–468`。
- 行为：seeds 采用 `live peers - queued peers`，这两个计数不能确定对方是否持有全部分片；文件 downloaded_bytes 直接取本地文件长度，且全局 finished 时把每个文件记为 f.len，包括未选文件。
- 触发：peer 只有部分分片；文件被预分配、存在未校验数据，或种子仅选择部分文件下载。
- 影响：种子数不真实，文件可显示 100% 但内容仍未通过哈希校验；与“进度来自真实且已校验状态”要求冲突。
- 修改建议：只能展示引擎确知的 seeds，拿不到就明确未知；文件级进度从已校验分片与文件区间映射获得；保留真实 selected 状态，不把未选文件当完成。
- 验收：预分配文件、损坏已有文件、部分文件下载以及仅部分 bitfield 的 peers，均不应显示伪造完成度或 seeds。

### CORE-11：BT 输出路径与显示名混用

- 位置：`src-tauri/src/bt/mod.rs:270–283`、`813–845`、`883`；`.torrent` 初始名在 `src-tauri/src/manager.rs:767–781`；打开文件入口 `src-tauri/src/lib.rs:505`。
- 行为：输出目录用添加前 task.file_name，磁力元数据回来后又改写 file_name；删除、打开仍按 destination/file_name 计算，未保存实际 output_folder。单文件种子也会因为有名字而被当作“多文件目标”放入子目录。`.torrent` 名字来自外部文件名且 metadata_ready 已为 true，不会通过元数据过渡纠正。
- 触发：磁力 dn 与真实种子名不同；无 dn 的磁力；用户重命名过外部种子文件；单文件种子。
- 影响：打开文件/文件夹、删除、重启后的数据定位可以指向不同路径，用户认为未下载或删不掉；“边看边下”也会受影响。
- 修改建议：分别保存 display_name、真实 torrent name、实际输出根与文件清单；使用引擎句柄输出路径作为权威，不能从显示名反推物理路径。
- 验收：以上四种输入都记录真实路径；下载中、完成、暂停、重启后打开和删除保持一致。

### CORE-12：校验 I/O 失败会留下“校验中”

- 位置：`src-tauri/src/manager.rs:1327–1349`；自动校验调用 `1743–1744`。
- 行为：先把 Verifying 写入数据库；随后 `digest_file(...).await?` 若失败直接返回，没有写 Failed。自动完成路径又忽略 verify_checksum 的 Err。
- 触发：下载完成后文件被移走、锁定或读权限改变，自动/手动校验读取失败。
- 影响：worker 已结束但任务仍“校验中”，没有明确的失败原因和可恢复操作。重启恢复不替代本次运行中的正确状态反馈。
- 修改建议：所有校验出口统一落终态；I/O 错误写入可操作中文原因并发事件，保留已下载文件；不能忽略自动校验失败。
- 验收：校验前删除、锁定、拒绝读取目标；状态必须转 Failed 并保留操作入口；校验错误不得发完成提示或执行完成动作。

### CORE-13：删除失败被吞掉，界面可能假成功

- 位置：`src-tauri/src/manager.rs:879–899`、`920–946`；`src-tauri/src/bt/mod.rs:350–385`。
- 行为：删除目标文件、BT remove、BT pause 超时都忽略结果；随后直接移除或归档任务记录。BT remove 先删 binding 再等待 delete，失败时失去应用侧可管理句柄。
- 触发：文件被其他程序占用、权限不足，或 librqbit 暂停/删除超过一秒。
- 影响：用户选择“同时删除文件”后记录消失但文件仍在；更严重时引擎可能仍有活动任务而界面已移除。暂停失败也会被报告为成功。
- 修改建议：把“未找到可忽略”和“确实失败”分开；必要资源停止成功后才移除 binding/记录；失败返回具体中文原因并允许重试，不能无条件继续。
- 验收：锁定下载文件、模拟引擎暂停/删除超时，必须保留足够记录和操作入口；后台不得继续读写已经宣称移除的任务。

### CORE-14：做种完成与下载完成混在一个生命周期

- 位置：`src-tauri/src/bt/mod.rs:754–778`；统一完成通知 `src-tauri/src/manager.rs:1722–1753`。
- 行为：引擎已 `stats.finished` 时，若开启做种且尚未达到分享率，poll_until_finished 继续循环，直到做种目标满足才返回 Ok。因此统一 Completed 状态、完成通知和队列槽位释放都等到此时；分享率为 0 表示不限时做种时可以一直不返回。
- 触发：开启做种后下载完成但无人向本机请求分片，或设不限分享率。
- 影响：文件已经可用，用户却收不到及时完成通知；下载任务可能长时间占用并发名额，后续队列被阻塞。
- 修改建议：下载完成只触发一次完成事件和可操作提醒，做种使用独立状态/独立并发预算；停止做种不能把已完成下载回退成未完成状态。
- 验收：开/关做种、有限/无限分享率、没有 leechers 时，下载哈希完成即通知并释放下载名额；做种状态继续真实展示。
