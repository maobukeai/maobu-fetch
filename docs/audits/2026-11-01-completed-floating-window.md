# 下载完成悬浮条保留与快捷操作

日期：2026-11-01。基于当前 0.10.12 工作区；本轮不发布安装包。

## 交互方案

- 下载中继续显示真实进度；最后一个活动任务完成后，转换为“已完成 N 项”小条，保持 224×28 的紧凑尺寸。
- 每个完成项默认保留 180 秒，最多保留最近 6 个。详情默认显示 3 个，可展开到 6 个；进行中与已完成并存时使用小页签。
- 紧凑条可直接打开最近文件、打开文件夹、关闭；展开后可操作具体完成项。
- 鼠标悬停、键盘焦点及打开操作暂停剩余保留时间，离开后接着倒计时。打开文件后即使其他程序获得焦点，只要鼠标仍停在悬浮条上，就继续暂停计时。
- 打开失败时保留错误提示，并重新给予该项 3 分钟，方便重试。错误不回显可能包含凭证或路径的底层原文。
- 手动关闭清空当前完成提醒；新的完成项可以重新出现。提醒过期或关闭不会删除任务记录、改变下载文件。
- 只捕获本次运行观察到的真实下载完成事件，不把启动时的已完成历史重新弹出来；重复终态、BT 做种状态更新不会刷新保留时间。

这替代此前“无活动任务即立即隐藏”的完成行为；暂停或失败本身不被伪装成下载完成。

## 实现与边界

后端将短期完成列表、单调时钟、任务安全视图和文件动作拆成独立小模块。每项记录剩余时长，后台只在任务事件、交互变化或下一项到期时唤醒，没有新增全量轮询或每秒计时请求。

快照新增 `completed_tasks` 与 `completed_count`，继续保留原活动任务字段的含义。前端对新字段使用可选读取，旧后端缺少完成字段时不调用新命令；本轮没有数据库迁移或用户设置字段变更。

新增命令：

- `progress_window_set_interacting(interacting)`：报告交互保持意图。
- `progress_window_open_completed(taskId, target)`：仅接受 `file` / `folder`，检查近期完成资格和当前真实任务状态，复用现有任务路径校验，不接受任意文件路径。

打开操作使用 RAII 释放计时暂停，异步调用取消或错误不会让计时永久挂起。关闭、删除、重试、禁用后到达的迟发交互或操作结果不会复活旧提醒。页面重新挂载会通过同一个串行队列发送初始交互意图，释放重载前可能残留的保持状态。
