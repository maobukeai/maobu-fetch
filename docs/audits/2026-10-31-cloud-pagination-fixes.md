# M12：网盘目录分页、去重与完整性修复

日期：2026-10-31（Asia/Shanghai）。范围：百度网盘、夸克、123云盘、PikPak、蓝奏云的分享目录枚举。

## 已修改

原百度和 123 每目录固定第一页，夸克/PikPak 达 300/200 文件或 40/35 目录即返回当前结果。现四个平台均通过各自真实请求/解析 Source 接入共享目录遍历：百度 `page/num`、夸克 `_page/_size`、123 `page/next`、PikPak `page_token/next_page_token` 持续读取，保留文件 ID 去重及父子路径。重复条目不重复计数；分页总数变化、同 ID 元信息变化、重复游标/无进展、提前结束或最终数量不一致均返回错误。

蓝奏目录请求原固定 `pg=1`，第二页及后续文件因此缺失。现单独的分页模块逐页递增 `pg`，直到明确的成功空数组或已知终页状态；不猜测固定页大小。按文件 ID 去重并核对同 ID 名称/大小，第二页错误、异常终页、缺少数组、重复无进展及任何保护上限均报“列表未完整”，不返回部分成功。需要提取码与错误提取码保持不同结果。蓝奏每页最长 20 秒，条目、页数、响应与元数据预算与共享限制一致；其文件夹接口返回文件列表，不将没有协议证据的嵌套目录强行解释成其他平台的树形结构。

请求失败、非成功 HTTP、非 JSON、响应缺字段和子目录失效不会继续返回已经取得的部分列表。错误说明“文件列表未完整”，前端已有错误通道可呈现；不新增公开序列化字段，也不把不完整结果包装为可全选下载的成功列表。受保护分享仍沿用明确的需要提取码状态。

新增可取消的 `inspect_*_share_with_cancel(...,&CancellationToken)` 兼容入口，以及由产品使用的 `inspect_*_share_with_context(...,&CloudRequestContext)`，覆盖整个解析过程，包括初始分享页、验证码/访问令牌和所有目录页。旧签名保留为兼容 wrapper。每次解析总限 120 秒；每页请求最长 20 秒、响应最大 4 MiB。共享保护上限为 20,000 条目、2,000 个目录、每目录 1,000 页、128 层、累计 32 MiB 条目元数据。触发任何保护均明确失败并建议缩小目录，不能静默返回前面部分。

PikPak 原“选定子目录失败/为空就改读根目录”的行为已去除：失效子目录必须失败，空目录保持空目录，避免用户选择的范围被扩大。原在线 fallback 测试也已改名、改断言，要求失败且不返回根目录文件。现有需要显式自有样本的在线 tests、ignore 条件和隐私保护均保留。

继续复查发现夸克虽解析 `pdir_fid`，实际枚举仍固定根目录 `0`。现将链接中选定目录传入真实分页 Source，空目录保持空，失效目录明确失败，不能回根扩大范围。公开入口和 DTO 均不变。

生产代码拆分到四盘各自的 listing/models 小模块和蓝奏 pagination 模块，共享 HTTP/遍历单独维护；现有公开 DTO 字段和 serde 命名保持不变。总大小加法检查溢出。错误不包含响应正文、Cookie、密码、签名、分享标识、文件名或临时直链。

## 行为复验

```powershell
powershell -NoProfile -File scripts/audit/run_cloud_pagination_probe.ps1
```

历史独立 Source 探针实际结果：**4 passed / 0 failed / 0 ignored**。四个平台各执行 22 个场景，共 **88 个本地 HTTP 场景**。后续分页请求已复用生产 CloudRequestBuilder 的逐跳 Cookie/取消/代理逻辑，脚本因此改为运行正式 Cargo 的 `pagination` 过滤，不再维护另一个脱离真实请求器的 standalone shim；所有 Source、DTO 和目录遍历仍是生产实现。

包含新增蓝奏的正式 Cargo 复验：

```powershell
cargo test --manifest-path src-tauri/Cargo.toml --lib pagination -- --nocapture
```

实际结果：**8 passed / 0 failed / 0 ignored**，运行 0.14 秒；包括上述四盘 88 场景和蓝奏 4 个测试中的 **15 个本地 HTTP 子场景**。蓝奏覆盖 101 个文件跨两页及第三次请求确认终页、重复 ID、两种空目录、第二页 HTTP/JSON/字段/重复/假终页失败、静默请求取消、提取码缺失与错误，以及页数/条目/元数据保护上限。所有用例进入真实生产分页方法。

另运行 `cargo test --manifest-path src-tauri/Cargo.toml --lib quark::selection_tests -- --nocapture`：**1 passed / 0 failed / 0 ignored**，0.03 秒。实际 `inspect_quark_share_with_context` 完成 token 请求后，对指定子目录完整枚举 301 文件（4 页）、返回空目录、拒绝失效目录三个场景，服务端逐次断言从未请求分享根目录。

统一请求器接入后的最新 Cargo 正常重链 EXE 复验：`pagination` **9 passed / 0 failed / 0 ignored**，0.13 秒；上述四盘 88、蓝奏 15、夸克选择范围 3，合计 **106 个本地 HTTP 场景**。目录请求与初始分享页/令牌阶段共用同一生产上下文，不再通过裸 Client 绕过逐跳 Cookie 作用域。

后续正式全量 Cargo 历史当轮 **1412 passed / 2 failed / 16 ignored**，本专项上述 9 项全部通过；两个失败分别属于请求头非法 Cookie fixture 和混合带宽 fixture 的磁盘计数，当时没有将本专项通过等同整套成功。修正 fixture 并保留原断言后 round6 已统一通过；设置持久化兼容修复后的 round7 为 **1432 passed / 0 failed / 16 ignored**，另 9 项 Range 回归全部通过；历史失败诊断仍在原生 manager 专项中保留。后续公网适配修复后的最新完整 round10 为 **1471 passed / 0 failed / 16 ignored**，另 9 项 Range 全通过；该增量索引不改写前述历史。

四盘各覆盖 101、201、301 文件完整枚举，重复条目去重，80 层目录完整路径，第二页 HTTP 失败/畸形 JSON/重复页/提前空页，子目录 404 不降级部分成功，文件总大小溢出，API 业务错误、无效总数/游标、分页期间总数变化，以及条目、目录、页数、深度、元数据预算、超时和取消保护。错误用例均断言返回 Err，无可误用的部分结果，并确认合成密码、Cookie、签名和分享标识不出现在错误中。

本地服务只监听随机 127.0.0.1 端口，凭据和文件条目均为合成数据，没有读取个人 Cookie、数据库、账号信息或下载公网分享文件。

## 验证边界

这些平台的分享接口包含非公开协议；本批延续现有 endpoint 和字段，验证了生产分页请求、控制流和错误语义，不能替代真实平台当前可用性验收。尚未对用户自有的多页大分享进行在线测试；私有接口字段或风控变化仍可能需要适配，届时必须失败并说明，不能退回静默截断。

旧网盘函数独立创建 Client 导致应用代理/任务代理不一致的缺口，另归入 **M08-Cloud**，现已贯穿五盘全部阶段并通过 5 项本地认证代理回归，见 `2026-10-31-cloud-proxy-fixes.md`；两种测试分别验证分页完整性和请求出口，不互相代替。
