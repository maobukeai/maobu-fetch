## 3. 最需要先处理的问题

### 3.1 浏览器认证与页面授权

- **EXT-01**：所有网页都可注入的 LanDisk 监听入口，只靠固定 `postMessage` 字符串辨认请求，后台没有严格验证来源站点、目标和用户触发，可被页面伪造为携 Cookie 的 POST 下载任务。已用隔离入口复现，未向外部服务执行攻击。
- **EXT-02**：下载请求把目标域、来源页、Referrer 的 Cookie 拼成一条 Cookie 头。实际 Chrome/Edge API 已复现跨主机拼接，存在登录态发送到其他域的风险。
- **EXT-03**：代码依赖 Chrome/Edge Tab 不存在的 `cookieStoreId` 字段；对隔离无痕 Tab 调用认证头辅助函数时，读到了普通 store 的合成 Cookie，尚未完整运行无痕下载事件链路。

整改应同时覆盖域名、path、store、分区和重定向边界。不能只增加日志脱敏，也不能把页面自己能构造的字符串当作授权。

### 3.2 文件完整性和恢复

- **M01**：M3U8 合并后的 rename/copy 失败被吞掉，仍返回成功并删除正确分片。实际输出仍是 5 字节旧文件，却报告 7 字节新数据。
- **M02**：M3U8 BYTERANGE 收到 200 全量响应仍合并。应为 8 字节的内容实际输出 16 字节重复数据。
- **M03/M04**：不支持的加密可直接写出密文；已有非空分片即被信任，损坏分片 `BAD` 能被合并为成功结果。
- **CORE-01/02**：ETag 错用不区分大小写比较；普通单连接续传只看 206，没有验证 Content-Range。
- **CORE-07**：BT 文件归属与同名路径不安全，删除整目录可能删除非任务文件。已在临时目录中复现无关哨兵文件被删除。

验收必须检查磁盘实际内容、长度、哈希、恢复文件是否保留，不能只断言函数返回 Ok 或任务状态为完成。

### 3.3 下载状态与控制

- **CORE-03/04/05**：部分 Range 错误重试计数会重新开始；单连接部分网络等待未被取消和总超时覆盖；快速暂停/恢复存在 worker 重叠风险，最后一项仍待端到端时序复现。
- **CORE-06**：BT 开启 fastresume，却没有启用 librqbit 的 session persistence，配置隔离复现为 `session_persistence_enabled=false`。
- **CORE-08/09**：BT 文件选择方法是空实现；单任务限速没有接入引擎。
- **M05**：原生直播 M3U8 只下载当前快照就返回成功，没有持续刷新与录制生命周期。

### 3.4 用户可见的功能断链

- **M06**：默认清晰度可能优先选中无声视频，已有 FFmpeg 也不能保证默认有声。真实 YouTube 元数据中最高默认候选的 `acodec=none`，代码前后端均存在相应选择路径。
- **M07**：B 站多 P/番剧选集只有前端入口，后端没有生成 Collection/episodes 数据，不能宣称已支持整套选集。
- **APP-01/02/03**：刷新链接、拖放种子 Base64 预览、未保存 Tracker 来源的参数键与 Tauri camelCase 契约不符。不是所有 BT 功能都失效，具体兜底边界见契约报告。
- **EXT-04/05/06**：接管成功浮层的撤销发送不支持的动作；体积阈值被重置或被归档文件绕过；磁力遇鉴权/服务错误时回退不完整。
- **M12**：网盘目录分页和上限处理可能静默漏文件。

## 5. 已经落实的交互修改

### 完成提醒

1. 新增应用内完成提醒，默认 **30 秒**；设置支持 **15 秒、30 秒、60 秒、手动关闭**。
2. 提供 **打开文件、打开文件夹、查看详情** 三个入口；所有操作按后端任务 ID 执行，不从通知文本拼文件路径。
3. 鼠标悬停、键盘焦点、正在打开文件、窗口隐藏或失焦时停止自动关闭；恢复后重新给予完整停留时间。
4. 多个完成任务依次展示，提示剩余数量；关闭当前条目后显示下一条，避免直接覆盖前一条。
5. 打开失败显示错误并保留提醒，可以继续打开目录或查看任务；按钮执行中禁用，避免重复操作。
6. 查看详情会退出设置页、清除搜索及高级过滤、选择对应任务并展开详情。
7. 收到任务移除事件时同步清理对应提醒；删除后的旧通知不会继续指向不存在的任务。
8. 多类应用内提示改为堆叠显示，减少完成、失败、恢复和普通提示互相覆盖。
9. 长文件名限制为三行，完整内容保留在标题提示中；按钮可键盘聚焦，有明确焦点和禁用状态。新时长选择使用原生 select，避免复用现有 Select 的键盘缺陷。

### Windows 通知与兼容

- Windows Toast 请求使用现有库的 Long 模式。库定义为约 25 秒；最终显示仍受 Windows 通知设置、免打扰和系统策略影响，不能承诺精确时长。
- 设置文案改为“任务通知总开关”和“系统通知与应用内提醒”，明确两个开关共同控制的范围。**本轮没有新增相互独立的系统/应用内开关。**
- 清理通知订阅异步初始化的退出边界，迟到的订阅会立即解除。
- 新字段 `completion_notice_seconds` 有 serde 默认 30，前端读取也回退 30；后端仅接受 0/15/30/60。旧设置 JSON 可读取，0 可往返保存；没有数据库表迁移。
- 原有 Tauri 标识、数据库名、端口、分片后缀、协议头和命令名均保留。没有新增依赖。

实现位置：`src/components/CompletionToast.tsx`、`src/App.tsx`、`src/components/settings/SettingsPage.tsx`、`src/styles.css`、`src/types.ts`、两种语言文件、`src-tauri/src/models.rs`、`src-tauri/src/manager.rs`。

### 交互实测边界

`pnpm run audit:ui` 在真实 Edge 内渲染产品 React 组件和样式，调用层使用替身，不修改真实设置或打开个人文件。实际等待验证了 30 秒提醒悬停时保持、15 秒自动关闭、排队、打开失败反馈、目录入口、设置保存载荷。测试了 500 条可见任务、多选/半选/全选、文件名双向排序、搜索后定位与详情展开。

## 6. 发布与构建额外问题

### REL-01 · P2：EXE 的 OriginalFilename 为空

本轮实际读取 release EXE：ProductName=`Maobu Fetch`，ProductVersion/FileVersion=`0.10.11`，OriginalFilename 为空。前两项正确，最后一项不满足 AGENTS.md §10 的属性核验要求。应在资源生成中补全并重建后实测。

### REL-02 · P2：release EXE 仍包含绝对开发者路径

对实际二进制执行字节检查，发现 `C:\Users\20269` 形态路径；没有把完整二进制字符串或可能相邻的敏感内容写入报告。不能因此认定存在凭据泄露，但违反发布产物不携绝对开发路径的约束。应配置路径重映射并检查源码宏、依赖 panic 路径和资源编译输出，再扫描最终包。

### REL-03 · P2：扩展构建会写入已安装目录，且错误被吞掉

`extension/build.mjs:18` 起在检测到 `%APPDATA%/app.lumaget.desktop/extension` 时，除了生成 `extension/dist`，还会覆盖已安装扩展的 manifest/src 并删除指定旧文件，整个过程的异常被 catch 忽略。本环境确实存在该目录，因此本轮第一次执行既定 `extension:build` 时走到了这个写入分支；本轮未修改扩展产品源码，复制内容来自当前仓库。

应把“构建”与“部署到已安装目录”拆为显式操作；构建默认只写产物目录，部署时核验路径并报告结果。这样测试不会顺带更换正在使用的扩展，也不会出现脚本报告通过而部署实际失败。

### 安装包检查

NSIS 和 MSI 基础包均小于 30 MB。使用 7-Zip 查看 NSIS、MSI CAB，并读取 MSI File 表：主有效载荷为 `maobu-fetch.exe`，没有发现 `yt-dlp.exe`、`ffmpeg.exe`、`ffprobe.exe`。扩展 ZIP 在临时审查目录生成两种名称，二者内容与哈希一致；没有上传 GitHub。

本轮未执行安装/卸载、覆盖升级或重启后的安装验收。预先运行的客户端已经占用 127.0.0.1:17433；为保留它的任务状态，没有停止或替换该进程。因此对现有 `/v1/health` 的 0.10.11/ready 响应只作为环境观察，**不是新构建 EXE 的启动验收**。

最终构建与实测校验值记录在本报告末尾，不应把审查构建直接作为已经通过全部发布门禁的版本。
