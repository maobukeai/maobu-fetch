## 持久化、并发和文件归属细节

1. `Store::update_bt_progress` 只合并已存在 BT 行的运行字段，保留当前选择、任务限速、优先级和用户设置。已删除行不重新插入。
2. `Store::complete_bt_task` 在一个事务内只允许仍为 Downloading 的行提交 Completed。暂停/删除之后旧 worker 没有完成提交权；完成通知以成功提交为前提。
3. `update_bt_selection`、`update_bt_ownership`、`update_bt_seed_request` 各自只更新对应字段，不使用旧整行覆盖新进度。
4. 引擎共享一个 Session 和一个生产 DHT；注册、控制和做种启动有串行边界，防止旧 handle 在删除后再次启动。做种独立容量使用设置中的 concurrent_downloads（1～32），不消费下载 worker 名额。
5. 历史累计上传字节保存在 BtTaskMeta，用于重启后的分享率；未知新增字段安全默认，旧 JSON/SQLite 行继续可读。
6. 旧版本路径恢复优先使用原始 URL，而非会被元数据覆盖的 file_name。找不到确定旧目录且已有数据时不会偷偷分配新根重新下载。歧义保留并报中文原因；人工“定位已有目录”流程仍需完整 UI 验收。
7. 删除文件仅逐个移除清单内的普通文件，目录只做 remove_dir 空目录清理。没有递归删除用户下载目录或按显示名盲删整个目录。

## 本轮额外发现和修复

- librqbit fastresume 抽样 `check_piece()` 返回 `Result<bool>`，原代码只检查 `is_err()`，把哈希不符的 `Ok(false)` 也当作通过；已单行修正为只接受 `Ok(true)`。
- 原生异步 bitfield flush 不保证暂停/退出时已落盘。已增加同步 write + sync_all，并按 revision 拒绝较旧异步快照覆盖新快照。
- `.torrent` 写入和 native 删除持久化失败原来仅打印日志。已改为可传播的错误，失败时保留内存条目供重试。
- 初始化期间 resume 会丢掉 peer stream/最新暂停意图，真实 loopback seeder 先暴露“永远 Paused”问题；已修复并重跑实际下载。
- streaming_priority 原来未接入。现在 true 时所有已选文件的首尾分片先于任何普通中间片，真实播放器 stream 的优先级仍最高；false 保留原生逐文件顺序。透明 TCP 代理记录真实 peer Request 验证，不伪造进度或 stream。
- 进度差不能当成网络速度：恢复时磁盘重检也会提高 verified progress。已改为 native LiveStats 的真实网络速度估计器，累计上传另行从 native 计数维护；补“存在半个种子、无 peers、速度必须为零”回归。
- 单任务 `per_task_speed_limit` 已是 bytes/sec，与全局 `speed_limit_kbps` 不同。本轮明确纠正单位并覆盖 1000→1000 bps 的上下行测试，只有全局 kbps 设置乘 1024。
- 旧 inline 校验仅检查 `d` 字典头，截断 Bencode、零分片长度、溢出总长和 Windows 重名路径都可能漏过。现在完整解析、20MiB 有界读取、checked 总长、哈希数量与合法路径校验；native 远端磁力元数据也设 shape guard，防止绕过应用校验。
