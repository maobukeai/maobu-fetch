# 重试与超时数值边界补充检查

日期：2026-10-31。

## 确认的问题

- 任务级连接超时只有非零检查，没有与现有 UI 的 600 秒上限一致；全局 default_retry_policy 未走同一套字段校验。
- 总时限、初始/固定退避等字段可接收极端 u64，产生不合产品预期的长期等待。旧记录和导入 JSON 也会进入运行时，不能只校验设置 UI。
- 下载客户端只读取全局连接超时，任务级“单连接超时”覆盖没有接入实际客户端构造。
- RetryPolicy 缺少结构级安全默认，旧的部分 JSON 策略不能补齐新字段。

没有把极端数值一概宣称为已复现 panic：锁定 Tokio 1.53.0 的 sleep/timeout 自身使用 checked_add；当前 media_publication 也已有 checked_add。此次补充用于统一输入契约、避免异常等待，并保证运行旧记录时使用可表示的有界时限。

## 修改契约

| 字段 | 新写入允许范围 |
| --- | --- |
| 单连接超时 | 1–600 秒，与现有编辑器一致 |
| 总任务时限 | null 表示无限；1–31,622,400 秒（366 天） |
| 重试次数 | 0–32 |
| 初始与最大退避 | 1–3,600,000 毫秒，最大值不少于初始值 |

统一逻辑拆入 manager/retry_policy.rs。设置与任务更新入口对新非法值返回明确中文错误；运行时只归一化旧策略的副本，不重写原始数据库或用户文件。旧 Some(0) 延续原先“无总时限”的运行语义；超大非零时限与退避钳位到上述范围。固定和指数退避都受同一上限约束，尝试次数的移位与乘法不会溢出。

RetryPolicy 加入 serde(default)，缺失字段使用原默认值。任务整体覆盖仍优先于全局，覆盖中的总时限 null 表示该任务明确无限，不回落到全局总时限。

## 验证状态

新增 8 组行为测试覆盖允许边界、至少一年和无限时限、非法新输入的中文拒绝、旧极端记录归一化且原值不变、固定/指数退避上限、部分 JSON/旧设置默认、真实设置校验入口、公开有效策略选择，以及超大旧时限归一化后可及时取消。
